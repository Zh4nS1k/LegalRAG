# Legal RAG Tester

A production-ready Python project for evaluating LLMs on legal questions using Retrieval-Augmented Generation (RAG) with Pinecone.

## Prerequisites

- Python 3.11+
- Pinecone API Key and an existing Index
- Groq API Key
- Input Excel file with questions

## Installation

1. Clone or copy the project files to your local machine.
2. Install the required dependencies:
   ```bash
   pip install -r requirements.txt
   ```

## Configuration

Copy the template `.env` file and fill in your keys and settings:

```bash
cp .env.example .env
```

Edit `.env` to include your specific credentials:
- `PINECONE_API_KEY`: Your Pinecone API key
- `PINECONE_INDEX_NAME`: The name of your Pinecone index
- `GROQ_API_KEY`: Your Groq API key
- Configure `LLM_MODELS` with a comma-separated list of models to test.

## Input Excel Format

The application expects an `.xlsx` file (e.g., `questions.xlsx`) with at least the following:
- A header row.
- A column named `question` containing the legal questions.
- (Optional) A column named `id` containing an identifier for each question.

## Usage

Run the pipeline using the CLI:

```bash
python main.py
```

### Optional Arguments

- `--input <path>`: Override the input Excel file path.
- `--output <path>`: Override the output Excel file path.
- `--models <models>`: Override the models to test (comma-separated, e.g., `gpt-4o,claude-3-5-sonnet-20240620`).
- `--limit <N>`: Process only the first N questions.
- `--skip-low-limit`: Skip low-limit models like `llama-4-maverick`
- `--dry-run`: Embed and retrieve chunks only, print the results without calling any LLM APIs.

Example:
```bash
python main.py --input test_questions.xlsx --limit 10 --dry-run
```

## Output Format

The output is written to an `.xlsx` file (e.g., `results_YYYYMMDD_HHMMSS.xlsx`). It contains the following columns:

| Column | Description |
|---|---|
| id | Question ID |
| question | The original question text |
| model | The LLM model name |
| answer | The generated answer from the LLM |
| answer_raw | The raw response (with think tags for models like DeepSeek R1) |
| chunks_used | Number of context chunks provided to the LLM |
| avg_score | Average Pinecone retrieval score for the chunks |
| latency_ms | Request latency in milliseconds |
| prompt_tokens | Tokens used in the prompt |
| completion_tokens | Tokens generated by the model |
| error | Any error messages encountered during API calls |
